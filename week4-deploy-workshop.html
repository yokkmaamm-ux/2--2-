    ส่วนที่ 0

    เตรียมโปรเจกต์และเครื่องมือ

    ทำส่วนนี้ครั้งเดียว ใช้ร่วมกันทั้งสองแบบ ถ้าเว็บพังตั้งแต่ในเครื่อง ขึ้น Server ไปก็จะพังเหมือนเดิม จึงต้องเตรียมให้เรียบร้อยก่อน

    0.1

    สร้างโฟลเดอร์ my-site และจัดไฟล์ให้เป็นระเบียบ

    สร้างโฟลเดอร์ใหม่ชื่อ my-site แล้ว copy งาน Responsive จาก Week 3 มาใส่ จัดไฟล์ให้ได้โครงสร้างแบบนี้

    my-site/ ├── index.html ├── css/ │ └── style.css └── images/ └── hero.jpg
    ทำไม

    Hosting จะอัปโหลด "ทั้งโฟลเดอร์" ขึ้นไป ไฟล์ที่อยู่นอกโฟลเดอร์นี้ เช่น รูปที่ยังค้างอยู่ใน Downloads จะไม่ถูกส่งขึ้นไปด้วย การเก็บทุกอย่างไว้ในโฟลเดอร์เดียวจึงเป็นการบอกว่า "นี่คือเว็บทั้งหมดของเรา"

    ผลที่ควรเห็น

    เปิดโฟลเดอร์ my-site แล้วเห็นไฟล์และโฟลเดอร์ย่อยครบ ไม่มีไฟล์เว็บอยู่ข้างนอก

    0.2

    ตั้งชื่อหน้าแรกเป็น index.html

    ถ้าหน้าแรกชื่ออื่น เช่น home.html ให้เปลี่ยนชื่อเป็น index.html แล้วแก้ลิงก์ที่ชี้ไปหน้านี้ให้ตรงด้วย

    ทำไม

    เมื่อมีคนเปิด https://ชื่อเว็บ.web.app โดยไม่ระบุไฟล์ Server จะหาไฟล์ชื่อ index.html มาแสดงเป็นหน้าแรกโดยอัตโนมัติ ถ้าไม่มีไฟล์นี้ จะเจอหน้า 404 Not Found

    ระวัง

    Windows มักซ่อนนามสกุลไฟล์ ไฟล์ที่เห็นว่า index.html อาจเป็น index.html.txt ให้เปิด File Explorer → View → ติ๊ก File name extensions เพื่อตรวจ

    0.3

    ตรวจ path และชื่อไฟล์ทุกไฟล์

    1. ทุก src และ href ต้องเป็น path แบบ relative เช่น images/hero.jpg ห้ามเป็น C:\Users\...
    2. ชื่อไฟล์ใช้ตัวพิมพ์เล็ก ไม่มีเว้นวรรค ไม่มีภาษาไทย เช่น cat-01.jpg
    3. ชื่อใน code ต้องตรงกับชื่อไฟล์จริงทุกตัวอักษร รวมถึงนามสกุล .jpg กับ .JPG
    ทำไม

    บน Server ไม่มีไดรฟ์ C:\ ของเรา path แบบเต็มจึงหาไฟล์ไม่เจอ ส่วน path แบบ relative หาไฟล์จากตำแหน่งของหน้าเว็บเอง จึงใช้ได้ทุกที่

    Windows มองว่า Cat.jpg กับ cat.jpg เป็นไฟล์เดียวกัน แต่ Server ส่วนใหญ่ถือว่าเป็นคนละไฟล์ นี่คือสาเหตุอันดับหนึ่งที่ "ในเครื่องรูปขึ้น แต่ขึ้นเว็บแล้วรูปหาย"

    0.4

    ทดสอบในเครื่องด้วย Live Server และ Console

    1. ใน VS Code เลือก File → Open Folder → เลือกโฟลเดอร์ my-site
    2. เปิด index.html แล้วกด Go Live มุมขวาล่าง
    3. ในเบราว์เซอร์กด F12 → แท็บ Console
    ทำไม

    Live Server เปิดเว็บผ่าน http:// คล้ายกับ Server จริงมากกว่าการดับเบิลคลิกไฟล์ ข้อความสีแดงใน Console คือไฟล์ที่หาไม่เจอหรือโค้ดที่ผิด แก้ตอนนี้ง่ายกว่าแก้หลังขึ้นเว็บแล้ว

    ผลที่ควรเห็น

    ทุกรูปและสไตล์แสดงครบ Console ไม่มีข้อความสีแดง (เช่น 404 (Not Found))

    0.5

    ติดตั้ง Node.js และเปิด Terminal ใน VS Code

    1. ไปที่ nodejs.org ดาวน์โหลดเวอร์ชัน LTS แล้วติดตั้งตามค่าเริ่มต้น
    2. ปิด VS Code แล้วเปิดใหม่ จากนั้นเปิด Terminal: เมนู Terminal → New Terminal
    3. พิมพ์คำสั่งตรวจสอบ
    Terminal
    node -v
npm -v
    ทำไม

    เครื่องมือ Deploy ของทั้ง Firebase และ Vercel แจกจ่ายผ่าน npm ซึ่งเป็นตัวติดตั้งโปรแกรมที่มากับ Node.js ต้องปิดเปิด VS Code ใหม่เพื่อให้ Terminal รู้จักคำสั่งที่เพิ่งติดตั้ง

    ผลที่ควรเห็น

    ขึ้นเลขเวอร์ชันทั้งสองบรรทัด เช่น v22.x.x และ 10.x.x (ตัวเลขจริงขึ้นกับรุ่นที่ติดตั้ง)

    ระวัง

    ถ้าขึ้น running scripts is disabled on this system ให้กดลูกศร ˅ ข้างเครื่องหมาย + ในแผง Terminal แล้วเลือก Command Prompt แทน PowerShell

    แบบที่ 1

    Deploy ด้วย Firebase Hosting

    อัปโหลดจากเครื่องเราขึ้น Server ของ Google โดยตรงผ่าน Firebase CLI ได้ลิงก์ ชื่อโปรเจกต์.web.app

    1.1

    ติดตั้ง Firebase CLI

    Terminal
    npm install -g firebase-tools
firebase --version
    ทำไม

    CLI (Command Line Interface) คือโปรแกรมที่สั่งงานด้วยการพิมพ์คำสั่ง firebase-tools ทำให้เราสั่ง Firebase จาก Terminal ได้ ส่วน -g (global) ทำให้ใช้คำสั่ง firebase ได้จากทุกโฟลเดอร์ ติดตั้งครั้งเดียวต่อเครื่อง

    ผลที่ควรเห็น

    คำสั่งที่สองแสดงเลขเวอร์ชันของ Firebase CLI

    1.2

    Login ด้วยบัญชี Google

    Terminal
    firebase login

    ถ้ามีคำถามเรื่องส่งข้อมูลการใช้งาน ตอบ n ได้ จากนั้นเบราว์เซอร์จะเปิดขึ้นมา ให้เลือกบัญชี Google แล้วกด Allow

    ทำไม

    CLI ต้องรู้ว่าเราเป็นใคร และได้รับอนุญาตให้อัปโหลดไฟล์เข้าโปรเจกต์ในบัญชีของเรา เหมือนการ Login ก่อนอัปโหลดรูปขึ้น Facebook

    ผลที่ควรเห็น

    Terminal ขึ้นข้อความ Success! Logged in as อีเมลของเรา

    1.3

    สร้างโปรเจกต์ใน Firebase Console

    1. เข้า console.firebase.google.com ด้วยบัญชีเดียวกับขั้น 1.2
    2. กด Create a project ตั้งชื่อ เช่น gad-ชื่อเล่นภาษาอังกฤษ
    3. ขั้น Google Analytics ปิดได้ แล้วกดสร้างจนเสร็จ
    4. จด Project ID ไว้ (ดูได้ใต้ชื่อโปรเจกต์ หรือที่ Project settings)
    ทำไม

    โปรเจกต์คือ "พื้นที่ของเรา" บน Server ของ Google Project ID ต้องไม่ซ้ำกับใครในโลก และจะกลายเป็นชื่อในลิงก์เว็บ https://project-id.web.app เปลี่ยนภายหลังไม่ได้ จึงควรตั้งให้สื่อความหมาย

    ผลที่ควรเห็น

    เข้าหน้า Dashboard ของโปรเจกต์ได้ และรู้ Project ID ของตัวเอง

    ระวัง

    หน้าตา Console เปลี่ยนบ่อย ถ้าปุ่มไม่ตรงกับคำอธิบาย ให้มองหาคำว่า Create หรือ Add project บัญชีของมหาวิทยาลัยบางแห่งถูกปิดสิทธิ์ Firebase ถ้าสร้างไม่ได้ให้ใช้บัญชี Gmail ส่วนตัว

    1.4

    เชื่อมโฟลเดอร์กับโปรเจกต์ด้วย firebase init

    ตรวจให้แน่ใจว่า Terminal อยู่ในโฟลเดอร์ my-site (ถ้าเปิดโฟลเดอร์นี้ใน VS Code ไว้แล้ว Terminal จะอยู่ในนั้นอยู่แล้ว) จากนั้นสั่ง

    Terminal
    firebase init hosting

    ใช้ลูกศรขึ้นลงเพื่อเลือก กด Enter เพื่อยืนยัน แล้วตอบตามตารางนี้

    คำถามตอบทำไมตอบแบบนี้
    Please select an optionUse an existing projectเราสร้างโปรเจกต์ไว้แล้วในขั้น 1.3
    Select a default Firebase projectProject ID ของเราบอกว่าโฟลเดอร์นี้จะส่งขึ้นโปรเจกต์ไหน
    What do you want to use as your public directory?. (จุด)จุดแปลว่า "โฟลเดอร์ปัจจุบัน" คืออัปโหลดทั้ง my-site ที่มี index.html อยู่
    Configure as a single-page app?Noเว็บเรามีหลายหน้าเป็นไฟล์จริง ถ้าตอบ Yes ทุกลิงก์ที่หาไม่เจอจะถูกส่งกลับไปหน้าแรก
    Set up automatic builds and deploys with GitHub?Noวันนี้เราใช้ Auto Deploy กับ Vercel ในแบบที่ 2
    File ./index.html already exists. Overwrite?No เสมอถ้าตอบ Yes หน้าเว็บของเราจะถูกแทนด้วยหน้าตัวอย่างของ Firebase
    ทำไม

    firebase init ไม่ได้อัปโหลดอะไร มันแค่สร้างไฟล์ตั้งค่าเพื่อ "ผูก" โฟลเดอร์ในเครื่องเข้ากับโปรเจกต์บน Server ทำครั้งเดียวต่อโฟลเดอร์

    ผลที่ควรเห็น

    Terminal ขึ้น Firebase initialization complete! และใน my-site มีไฟล์ใหม่ firebase.json กับ .firebaserc (อาจมี 404.html เพิ่มมาด้วย ปล่อยไว้ได้)

    ระวัง

    ข้อความคำถามอาจต่างเล็กน้อยตามเวอร์ชันของ CLI ถ้าเผลอตอบ Overwrite = Yes ให้ copy index.html ของเราจากงาน Week 3 กลับมาทับ

    1.5

    เปิดดู firebase.json ให้เข้าใจ

    firebase.json
    {
  "hosting": {
    "public": ".",
    "ignore": [
      "firebase.json",
      "**/.*",
      "**/node_modules/**"
    ]
  }
}
    ทำไม

    "public" บอกว่าจะอัปโหลดโฟลเดอร์ไหน "ignore" คือรายการไฟล์ที่ไม่ต้องอัปโหลด เช่น ไฟล์ตั้งค่าเอง และไฟล์ที่ชื่อขึ้นต้นด้วยจุดอย่าง .firebaserc ซึ่งเป็นเรื่องของเครื่องเรา ไม่ใช่เนื้อหาเว็บ ถ้าตอบ public directory ผิดในขั้นก่อน แก้ค่าตรงนี้ได้เลยโดยไม่ต้อง init ใหม่

    1.6

    Deploy ขึ้น Server

    Terminal
    firebase deploy --only hosting
    ตัวอย่างผลลัพธ์
    === Deploying to 'gad-yourname'...
✔ hosting[gad-yourname]: file upload complete
✔ Deploy complete!

Hosting URL: https://gad-yourname.web.app
    ทำไม

    คำสั่งนี้ copy ไฟล์ทั้งหมดในโฟลเดอร์ขึ้น Server ของ Google แล้วกระจายไปยัง CDN ทั่วโลก --only hosting บอกให้ส่งเฉพาะส่วนเว็บ ไม่ไปแตะบริการอื่นของ Firebase

    ผลที่ควรเห็น

    ได้ Hosting URL กด Ctrl แล้วคลิกลิงก์ใน Terminal เพื่อเปิด หน้าเว็บต้องเหมือนตอนเปิดด้วย Live Server ทุกอย่าง และมีรูปกุญแจ (HTTPS) ในช่อง URL

    1.7

    เปิดบนมือถือ แล้วลองแก้และ Deploy ซ้ำ

    1. ส่งลิงก์เข้ามือถือตัวเอง (เช่น ส่งใน LINE หาตัวเอง) แล้วเปิดดู
    2. กลับมาที่ VS Code แก้ข้อความใน <h1> แล้วกด Ctrl + S
    3. รีเฟรชลิงก์เดิม สังเกตว่ายังไม่เปลี่ยน
    4. สั่ง firebase deploy --only hosting อีกครั้ง แล้วรีเฟรชด้วย Ctrl + Shift + R
    ทำไม

    การ Deploy คือการถ่าย "สำเนา" ไฟล์ขึ้นไป ณ เวลานั้น แก้ไฟล์ในเครื่องภายหลังจึงไม่ส่งผลกับเว็บจนกว่าจะ Deploy ใหม่ ส่วนการเปิดบนมือถือจริงคือการทดสอบ Responsive จาก Week 3 กับอุปกรณ์จริง ซึ่งแม่นกว่าโหมด F12

    ผลที่ควรเห็น

    หลัง Deploy ครั้งที่สอง ข้อความ h1 บนเว็บเปลี่ยนตาม ทั้งบนคอมพิวเตอร์และมือถือ ใน Console ของ Firebase → Hosting จะเห็นประวัติการ Deploy 2 ครั้ง

    Deploy ด้วย Vercel

    ทำ 2 ช่วง ช่วงแรกใช้ Vercel CLI ซึ่งคล้ายกับ Firebase ช่วงที่สองเชื่อมผ่าน GitHub ให้เว็บอัปเดตเองทุกครั้งที่ส่งโค้ดขึ้นไป ซึ่งเป็นวิธีที่ใช้ในการทำงานจริง

    2A · Deploy ด้วย Vercel CLI

    2.1

    สมัคร GitHub แล้วสมัคร Vercel ด้วยบัญชี GitHub

    ทำไม

    ในช่วง 2B เราจะให้ Vercel ดึงโค้ดจาก GitHub ไป Deploy เอง ถ้าสมัคร Vercel ด้วย GitHub ตั้งแต่แรก สองบัญชีจะเชื่อมกันอยู่แล้ว ไม่ต้องตั้งค่าเพิ่ม แพ็กเกจ Hobby ใช้ฟรีสำหรับงานส่วนตัว

    ผลที่ควรเห็น

    เข้า Dashboard ของ Vercel ได้ มุมซ้ายบนเป็นชื่อบัญชี GitHub ของเรา

    2.2

    ติดตั้ง Vercel CLI และ Login

    Terminal

    ผลที่ควรเห็น

    Want to modify these settings?noเว็บ HTML ธรรมดาไม่ต้อง Build อะไร ใช้ค่าที่ Vercel ตรวจเจอได้เลย
    ทำไม

    คำถามจะถามเฉพาะครั้งแรก คำตอบถูกเก็บไว้ในโฟลเดอร์ใหม่ชื่อ .vercel ในเครื่อง ครั้งต่อไปพิมพ์แค่ vercel ก็ Deploy ได้ทันที คำสั่งนี้สร้าง Preview คือเว็บเวอร์ชันทดสอบที่ยังไม่ใช่ลิงก์หลัก

    ผลที่ควรเห็น

    ได้ลิงก์ Preview หน้าตาประมาณ https://my-site-xxxxxxx-ชื่อบัญชี.vercel.app ที่มีรหัสสุ่มปนอยู่

    ระวัง

    ข้อความคำถามอาจต่างเล็กน้อยตามเวอร์ชัน ถ้าชื่อโปรเจกต์ซ้ำกับคนอื่น Vercel จะเติมคำต่อท้ายให้ ลิงก์ Preview บางครั้งต้อง Login Vercel ก่อนจึงเปิดได้ ซึ่งเป็นเรื่องปกติ

    2.4

    ขึ้นลิงก์หลักด้วย vercel --prod

    Terminal
    vercel --prod
    ทำไม

    Vercel แยกเว็บเป็น 2 ระดับ Preview มีลิงก์ใหม่ทุกครั้ง ใช้ทดสอบหรือส่งให้เพื่อนดูก่อน ส่วน Production คือลิงก์หลักที่สั้นและไม่เปลี่ยน แยกกันแบบนี้เพื่อไม่ให้งานที่ยังไม่เสร็จไปโผล่บนเว็บจริง

    ผลที่ควรเห็น

    ได้ลิงก์ Production เช่น https://my-site.vercel.app เปิดบนมือถือแล้วหน้าตาเหมือนลิงก์ Firebase ทุกอย่าง เพราะเป็นไฟล์ชุดเดียวกัน

    2B · เชื่อมเครื่องเรา → GitHub → Vercel (Auto Deploy)

    2.5

    ติดตั้ง Git และตั้งชื่อผู้ใช้

    1. ดาวน์โหลดจาก git-scm.com ติดตั้งโดยกด Next ตามค่าเริ่มต้น แล้วปิดเปิด VS Code ใหม่
    2. ตั้งชื่อและอีเมล (ใช้อีเมลเดียวกับบัญชี GitHub)
    Terminal
    git --version
git config --global user.name "Your Name"
git config --global user.email "you@email.com"
    ทำไม

    Git คือโปรแกรมในเครื่องที่บันทึกเวอร์ชันของไฟล์ เหมือนจุด Save ในเกมที่ย้อนกลับได้ ส่วน GitHub คือเว็บที่เก็บงานที่บันทึกไว้แบบออนไลน์ ชื่อและอีเมลจะติดไปกับทุกการบันทึก เพื่อบอกว่าใครเป็นคนแก้

    ผลที่ควรเห็น

    คำสั่งแรกแสดงเวอร์ชันของ Git คำสั่ง config ไม่แสดงอะไร (ไม่มีข้อความ = สำเร็จ)

    2.6

    สร้างไฟล์ .gitignore

    ใน my-site สร้างไฟล์ใหม่ชื่อ .gitignore (มีจุดนำหน้า ไม่มีนามสกุล) แล้วใส่

    .gitignore
    .vercel
.firebase
    ทำไม

    โฟลเดอร์ .vercel และ .firebase เป็นข้อมูลตั้งค่าและ cache ของเครื่องเราเอง ไม่ใช่เนื้อหาเว็บ ไฟล์ .gitignore บอก Git ว่าไม่ต้องส่งสิ่งเหล่านี้ขึ้น GitHub เพื่อให้ Repository สะอาด และไม่ให้การตั้งค่าของเครื่องเราไปปนกับระบบของ Vercel

    ผลที่ควรเห็น

    ในแท็บ Source Control ของ VS Code โฟลเดอร์ทั้งสองจะไม่อยู่ในรายการไฟล์ที่ต้องบันทึก

    2.7

    ส่งโปรเจกต์ขึ้น GitHub ด้วยปุ่มใน VS Code

    1. เปิดแท็บ Source Control (ไอคอนกิ่งไม้ด้านซ้าย หรือ Ctrl + Shift + G)
    2. กด Publish to GitHub แล้ว Login GitHub ในหน้าต่างที่เด้งขึ้นมา
    3. เลือก Publish to GitHub public repository และใช้ชื่อ my-site
    4. ถ้าถามว่าจะใส่ไฟล์ไหนบ้าง ให้เลือกทั้งหมด (โฟลเดอร์ใน .gitignore จะถูกข้ามให้อยู่แล้ว)

    หรือถ้าอยากใช้คำสั่งเอง ให้สร้าง Repository เปล่าชื่อ my-site บน github.com ก่อน (ไม่ต้องติ๊ก Add a README) แล้วสั่ง

    Terminal
    git init
git add .
git commit -m "first deploy"
git branch -M main
git remote add origin https://github.com/ชื่อบัญชี/my-site.git
git push -u origin main
    ทำไม

    ปุ่ม Publish ทำทุกคำสั่งข้างบนให้ในคลิกเดียว: init เริ่มให้ Git ดูแลโฟลเดอร์ add เลือกไฟล์ commit บันทึกเวอร์ชันพร้อมข้อความ remote บอกที่อยู่บน GitHub และ push ส่งขึ้นไป GitHub จะเป็น "สะพาน" ที่ Vercel มาดึงโค้ดไป Deploy

    ผลที่ควรเห็น

    เปิด github.com/ชื่อบัญชี/my-site แล้วเห็นไฟล์ index.html, css, images ครบ

    2.8

    Import Repository เข้า Vercel

    1. ใน Vercel Dashboard กด Add New… → Project
    2. ในหัวข้อ Import Git Repository หา my-site แล้วกด Import
    3. ตั้งชื่อโปรเจกต์ เช่น my-site-git (ห้ามซ้ำกับโปรเจกต์ที่สร้างในขั้น 2.3)
    4. Framework Preset เลือก Other ส่วน Build Command ปล่อยว่าง
    5. กด Deploy
    ทำไม

    การ Import คือการบอก Vercel ว่า "คอยเฝ้า Repository นี้ไว้" เลือก Other เพราะเว็บเราเป็น HTML ธรรมดา ไม่ได้ใช้ Framework อย่าง React หรือ Next.js จึงไม่มีขั้นตอน Build ให้ Vercel เสิร์ฟไฟล์ตามที่มีได้เลย

    ผลที่ควรเห็น

    หน้า Congratulations พร้อมภาพตัวอย่างเว็บ และลิงก์ ชื่อโปรเจกต์.vercel.app

    ระวัง

    ถ้าไม่เห็น Repository ของตัวเอง ให้กด Adjust GitHub App Permissions แล้วอนุญาตให้ Vercel เข้าถึง Repo my-site

    2.9

    ทดสอบ Auto Deploy

    1. แก้ข้อความใน <h1> หรือสีใน style.css แล้วกด Ctrl + S
    2. แท็บ Source Control พิมพ์ข้อความว่าแก้อะไร เช่น change title แล้วกด Commit
    3. กด Sync Changes (เทียบเท่าคำสั่ง git push)
    4. ดูแท็บ Deployments ใน Vercel แล้วรีเฟรชลิงก์บนมือถือ
    ทำไม

    เมื่อโค้ดใหม่ถูก push ไปที่ branch main GitHub จะแจ้ง Vercel ทันที แล้ว Vercel ดึงโค้ดล่าสุดไป Deploy เป็น Production ให้เอง เราจึงไม่ต้องพิมพ์คำสั่ง Deploy อีก และทุกเวอร์ชันมีประวัติใน GitHub ย้อนกลับได้เสมอ

    ผลที่ควรเห็น

    ในไม่กี่วินาทีจะมี Deployment ใหม่ขึ้นสถานะ Ready และเว็บบนมือถือเปลี่ยนตามที่แก้ โดยที่เราไม่ได้พิมพ์คำสั่ง deploy เลย
